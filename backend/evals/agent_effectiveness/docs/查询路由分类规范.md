# 高切坡智能查询问题路由分类规范

## 一、目标

为保证高切坡智能查询 Agent 在“能查、查得稳、可解释”三方面保持一致，本项目将用户问题统一分为 5 类，并要求后端路由、提示词、测试样例和前端返回口径保持一致。

## 二、五类分类规范

### 1. `db_query`

定义：
面向真实数据库事实的普通查询问题，重点是“查到什么”。

典型问法：

- 最近有哪些高切坡存在异常状态
- 查询渝北区高切坡数量
- 某个高切坡的基本信息是什么
- 最近有哪些预警记录

处理方式：

- 进入数据库查询主链路
- 由 Agent 选择候选表、生成 SQL、查库并返回表格与总结

### 2. `result_analysis`

定义：
需要在查到结果后再做归纳、对比、趋势提炼、重点提炼的问题，重点是“怎么看结果”。

典型问法：

- 帮我分析最近异常高切坡的分布情况
- 总结一下近一个月哪些区县风险更高
- 对比一下各区县高切坡异常数量
- 研判最近巡查异常的主要特征

处理方式：

- 先查询数据库
- 再基于真实结果表生成分析型总结
- `query_type` 返回 `result_analysis`

### 3. `template_query`

定义：
命中稳定业务模板的高频关键问题，重点是“不能让模型自由发挥口径”。

典型问法：

- 哪些高切坡处于异常状态，并告诉我属于哪一种异常类型

处理方式：

- 优先命中固定 SQL 模板
- 不走 LLM 自由选表选字段
- 查询结果再做业务总结

### 4. `clarify`

定义：
用户问题太短、太泛、条件缺失，暂时无法确定查询口径。

典型问法：

- 查一下
- 看看异常
- 帮我分析一下
- 查一下最近情况

处理方式：

- 不直接查库
- 返回补充建议
- 引导用户补充地区、时间、编号或异常类型

### 5. `out_of_scope`

定义：
问题与高切坡业务无关，或涉及账号、权限、系统管理等敏感信息。

典型问法：

- 查询系统账号密码
- 查看权限配置
- 今天天气怎么样
- 帮我写一段 Python 代码

处理方式：

- 直接拒答
- 返回高切坡业务边界提示

## 三、实现原则

1. `query_type` 是业务分类，不是执行细节分类。
2. 是否使用缓存 SQL、是否命中稳定模板、是否调用 LLM，属于执行实现，不应覆盖五类分类口径。
3. 同一个问题在不同执行路径下，`query_type` 应尽量保持稳定。
4. 前端展示、测试样例、阶段总结、接口文档应统一使用这五类分类名称。

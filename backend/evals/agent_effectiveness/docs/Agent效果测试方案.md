# 高切坡智能查询 Agent 效果测试方案

## 一、测试目标

本方案用于系统化评估高切坡智能查询 Agent 的实际效果，重点回答以下问题：

1. 问题路由是否正确；
2. SQL 查询口径是否正确；
3. 查询结果是否稳定、完整、可展示；
4. 查询报告是否忠于结果、是否具备“报告感”；
5. 模板查询、普通查询、分析型查询的边界是否清晰；
6. 面对口语问法、同义词、大结果集、空结果、越界问题时是否稳定。

---

## 二、测试范围

本轮测试覆盖 5 类问题：

1. `db_query`
2. `template_query`
3. `result_analysis`
4. `clarify`
5. `out_of_scope`

同时覆盖 4 类系统能力：

1. **路由能力**
2. **查询能力**
3. **结果展示能力**
4. **查询报告能力**

---

## 三、测试分层

建议把测试分成 3 层进行。

### 第 1 层：路由层测试

目标：

- 不依赖数据库，直接验证问题是否被正确分到 5 类；
- 优先发现路由规则过强/过弱、模板命中失效、越界拒答偏差等问题。

特点：

- 可在无数据库连接时执行；
- 运行快；
- 适合作为回归测试的第一道门。

输入：

- 问题文本

输出：

- `status`
- `query_type`
- `route_name`
- `reason`

---

### 第 2 层：查询执行层测试

目标：

- 在真实数据库环境中验证 SQL 口径是否正确；
- 检查查询结果是否为空、是否误查、是否漏查；
- 检查模板查询和普通查询的稳定性。

特点：

- 必须在能访问达梦数据库的环境中执行；
- 是判断系统“能不能查对”的核心层。

输入：

- 问题文本

输出：

- `query_type`
- `sql`
- `columns`
- `rows`
- `total_rows`
- `error`

---

### 第 3 层：查询报告与前端展示层测试

目标：

- 验证查询报告是否忠于结果；
- 验证大结果集是否能稳定展示；
- 验证分享、导出、移动端表现是否合理。

重点检查：

- 报告是否引用了结果表中不存在的信息；
- 报告条数是否与 `total_rows` 一致；
- 页面是否只显示样本结果但仍能正确显示总条数；
- 大结果集是否会造成“报告有结果，表格不显示”。

---

## 四、评估维度与评分标准

每题建议按 5 个维度评分，每项 `0 / 1 / 2` 分，总分 `10` 分。

### 1. 路由正确性

- `2`：路由符合预期
- `1`：可工作，但路由不理想
- `0`：明显路由错误

### 2. 查询结果正确性

- `2`：结果口径明显正确
- `1`：基本可用，但字段/过滤/排序有瑕疵
- `0`：明显错误、误查、空结果异常

### 3. 结果展示稳定性

- `2`：结果总数和样本展示都正常
- `1`：有结果，但展示细节有问题
- `0`：结果表格异常、空白或明显错乱

### 4. 报告忠实度

- `2`：报告完全基于结果
- `1`：基本忠实，但存在轻微过度概括
- `0`：明显编造、夸大或与结果矛盾

### 5. 报告格式质量

- `2`：结构清晰，像正式报告
- `1`：有报告结构，但表达较散
- `0`：只是摘要，不像报告

## 八、判定原则

### 1. 对查询结果的判定

优先看：

- 使用的表是否合理；
- 过滤条件是否符合业务；
- 结果是否明显违背题意；
- 是否出现“本不该为空却为空”的情况。

### 2. 对查询报告的判定

优先看：

- 是否引用了表格中不存在的数据；
- 是否把样本结果误当成全量结论；
- 报告中的数量是否与 `total_rows` 一致；
- 是否真的呈现“结论—发现—说明”的结构。

### 3. 对大结果集的判定

当前系统已调整为：

- 后端单独统计 `total_rows`
- 前端仅展示前若干条样本

因此判定重点不再是“是否返回了全部行”，而是：

- 是否正确显示总条数；
- 是否稳定展示样本；
- 是否在报告中说明“当前仅展示样本”。

## 九、当前已知风险点

基于最近迭代，当前重点风险包括：

1. 地区口语同义词问题，如“渝北地区”；
2. 大结果集导致前端结果表异常；
3. 分析型问题历史 SQL 缓存污染；
4. 模板查询与普通查询边界不清时的口径漂移；
5. 报告对样本结果的过度概括。

## 十一、结论

本方案建议采用：

```text
路由测试 -> 查询执行测试 -> 报告与展示测试
```

三层结构推进。

这样做的好处是：

- 即使数据库暂时不可达，也能先验证路由层；
- 真正连上库后，可以快速定位是“路由问题”“SQL 问题”还是“报告问题”；
- 适合做持续回归测试，也适合向导师汇报系统效果。

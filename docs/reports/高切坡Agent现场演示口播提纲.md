# 高切坡 Agent 现场演示口播提纲

## 1. 开场

这个系统的目标，是让业务人员不用懂数据库表名、字段名和 SQL，也能直接用自然语言查询高切坡业务数据。

可以把它理解为：

```text
业务人员说人话，系统自动转换成数据库查询，再把结果解释成人能看懂的业务结论。
```

## 2. 当前完成的核心能力

目前已经完成了几个关键能力：

第一，系统接入的是真实达梦数据库，不再单纯依赖设计文档。因为我们前期发现设计文档和真实库存在不一致，所以现在以真实数据库导出的 schema 为准。

第二，系统可以自动理解问题、生成 SQL、查询数据库，并把结果展示成表格。

第三，查询总结已经改成基于真实结果表进行分析。也就是说，表格是事实来源，总结是对表格结果的解释，避免模型自由编造。

第四，系统可以展示 Agent 的思考和工具调用过程，方便排查问题。

第五，已经支持中文语音输入和查询结果语音播报，适合现场快速演示和移动端使用。

## 3. 推荐演示问题

### 演示问题一

```text
我想知道最近有哪些高切坡存在异常状态
```

讲解点：

- 用户不需要知道表名字段名。
- 系统自动识别“异常状态”。
- 页面会显示 SQL、表格、总结和日志。

### 演示问题二

```text
我想知道哪些高切坡处于异常状态，并告诉我属于哪一种异常类型
```

讲解点：

- 这是高频业务问题。
- 系统会识别具体异常类型，比如裂缝、落石、坡面破坏、挡墙开裂、排水沟堵塞等。
- 异常类型会展示在结果表格里。
- 查询总结会基于这个表格再次分析。

### 演示问题三

```text
哪些高切坡最近出现裂缝或落石？
```

讲解点：

- 系统能理解“裂缝”“落石”这种地灾业务语言。
- 后端会映射到真实数据库字段。

## 4. 展示页面时按这个顺序讲

1. 输入自然语言问题。
2. 展示 Agent 思考过程。
3. 展示生成 SQL。
4. 展示查询结果表格。
5. 展示查询总结。
6. 点击结果播报。
7. 展示暂停、继续、停止。

## 5. 当前价值

当前版本的价值主要有三个：

第一，降低查询门槛。业务人员不用写 SQL。

第二，提高可追溯性。系统展示 SQL、日志和结果表，便于核查。

第三，形成可迭代基础。后续可以继续补充高频问题模板、字段解释和测试集，让系统越来越稳。

## 6. 当前边界

当前版本是阶段演示版，不是最终生产版。

后续还需要继续做：

- 业务人员校准字段含义。
- 补充更多稳定业务模板。
- 建立标准测试集。
- 加权限、日志审计、正式 HTTPS 证书和生产部署。

## 7. 结束语

当前系统已经完成了从“能生成 SQL 的原型”到“面向高切坡业务的智能查询 Agent”的转变。

后续重点不是再证明能不能跑通，而是围绕甲方高频业务问题，把查询口径和分析口径持续做稳。
